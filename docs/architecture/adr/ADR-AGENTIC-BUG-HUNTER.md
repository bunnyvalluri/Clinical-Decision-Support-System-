# ADR-0028: Integration of Agentic-Bug-Hunter as Controlled DevSecOps Tool

## Status
Accepted

## Context
Healthcare applications handling clinical risk prediction (BPY-CSE-2666) require continuous, rigorous security validation across authentication, authorization (RBAC), multi-tenancy (IDOR), API endpoints, and AI orchestration. However, unconstrained offensive penetration testing tools or autonomous internet scanning risk severe clinical disruption, data compromise, and regulatory violations.

We evaluate integrating `Agentic-Bug-Hunter` (v3.42.0) to provide structured vulnerability scanning and validation capabilities.

## Decision
We integrate `Agentic-Bug-Hunter` under a **controlled, policy-governed internal DevSecOps architecture**:
1. **Quarantined Security Layer**: The engine operates purely in a separate security testing layer decoupled from clinical request paths.
2. **Default-Deny Target Registry**: Strict `SecurityTarget` allowlist where every target must be explicitly approved with environment, protocol, port, and scope constraints.
3. **Evidence-Based 7-Question Validation Gate**: Rejects unprovable, theoretical findings.
4. **Zero PHI Exposure**: All security testing runs against synthetic datasets generated by `SyntheticSecurityDataGenerator`.
5. **Role-Based Isolation**: Patients, Doctors, and Nurses have ZERO access to security tooling. Informaticists have read-only access to AI/ML findings. IT Admins manage authorized scans.
6. **Mandatory Retesting**: No vulnerability can transition to `RESOLVED` without automated verification.

## Consequences
- Positive: High-fidelity vulnerability discovery without risk to patient safety or production data.
- Positive: Zero false positive noise in clinical reports due to the 7-question validation gate.
- Negative: Additional operational overhead to register and approve targets before scanning.
- Mitigation: Dedicated Celery background queue (`security_scans`) with strict timeouts and rate limits.
