# ADR-JULES-ENGINEERING-AUTOMATION: Google Jules API Integration for Engineering Automation

- **Status**: Accepted
- **Date**: 2026-09-18
- **Author**: Senior Multi-Disciplinary Engineering Team (Prompt 51)
- **Deciders**: Principal Architect, Security Lead, Medical Informaticist, Lead DevOps Engineer

---

## Context and Problem Statement

HealthNova AI is an enterprise healthcare application requiring high availability, rapid bug remediation, and continuous reliability. When CI builds fail, dependencies develop security vulnerabilities, or code review bottlenecks occur, manual triage creates latency.

Google provides the Jules REST API (`https://jules.googleapis.com/v1alpha`), a specialized coding agent capable of source code inspection, multi-turn bash execution, targeted code generation, and PR synthesis.

However, in a regulated healthcare environment governed by HIPAA and FDA guidance for Clinical Decision Support Systems (CDSS), autonomous code agents introduce significant risks:
1. Risk of modifying clinical scoring algorithms or patient diagnostic parameters.
2. Risk of leaking patient PHI or confidential API keys to cloud agent endpoints.
3. Risk of unreviewed code directly merging into production environments.

---

## Decision

We integrate the Google Jules REST API into HealthNova AI strictly as an **engineering-only, policy-governed subsystem** with the following structural guardrails:

1. **Strict Non-Clinical Separation**:
   - Jules is air-gapped from patient data and clinical models.
   - Code paths under `ml/`, `risk_scoring/`, `patients/` are protected by automated path policies in `JulesPolicyEngine`.

2. **Backend-Only Credential Isolation**:
   - `JULES_API_KEY` is restricted to backend environment variables.
   - All frontend communication routes through authenticated Django REST endpoints with RBAC role `IT_ADMIN`.

3. **Neon PostgreSQL as Single Authoritative Truth**:
   - All Jules sources, jobs, sessions, activities, artifacts, and approvals persist in Neon PostgreSQL.

4. **Mandatory Dual-Custody Approval**:
   - High-severity remediations require human approval before code execution proceeds.
   - Implementation plans generated by Jules require explicit IT Admin authorization.

5. **Branch Isolation**:
   - Protected branches (`main`, `master`, `production`) cannot be targeted.
   - Jules works on dedicated remediation branches (`jules/*`).

6. **Circuit Breaker Pattern**:
   - A resilient circuit breaker monitors upstream Jules availability, tripping open after 5 consecutive failures.

---

## Consequences

### Positive
- Rapid turnaround for CI failures, TypeScript errors, and lint regressions.
- Full compliance with clinical safety invariants: zero PHI exposure and zero autonomous diagnostic changes.
- Immutable audit ledger in Neon PostgreSQL tracking every action, prompt, and diff.
- Real-time visibility for IT Admins via WebSocket live streams.

### Negative / Trade-offs
- Upstream latency from Google Jules multi-turn planning.
- Additional administrative overhead for dual-custody review on sensitive branches.
